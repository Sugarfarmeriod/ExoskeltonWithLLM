# LLM Agent 与膝关节外骨骼论文前期汇报

## 一、目前的研究设想

本文拟在现有膝关节外骨骼实时控制系统之外增加一个 **LLM Agent**。它不直接生成力矩，而是接收实验目标和试次反馈，调用数据分析、历史比较、参数优化与安全检查工具，形成下一轮实验方案。

```text
实验目标 + 上一轮试次
          ↓
       LLM Agent
          ↓ 调用
数据分析 / 历史比较 / 参数优化 / 安全检查
          ↓
有界参数建议 + 依据 + 风险说明
          ↓
确定性检查 + 人工确认
          ↓
Simulink/Speedgoat 执行下一试次
```

核心边界是：LLM 只做低频规划和工具编排，实时控制仍由 `TestStructure.slx` 完成，最终安全权限仍属于参数边界、`Torque_Guard`、`SafeTorque` 和实验人员。

## 二、十篇代表论文

以下论文分成两组：前六篇回答“LLM Agent 怎样连接机器人技能与反馈”，后四篇回答“外骨骼有哪些可调用的控制与优化工具”。目前已对其中五篇核心论文核对本地 PDF 证据段落，其余依据本地全文 evidence card 与摘要整理；正式引用前仍需逐篇人工精读。

### 1. Do As I Can, Not As I Say: Grounding Language in Robotic Affordances（SayCan，2023）

- **做了什么：** LLM 对候选机器人技能与任务目标的匹配程度打分，技能价值函数判断当前状态下是否可执行，两类分数共同决定下一步技能。在真实厨房机器人上验证长任务规划。
- **可支持本文：** Agent 不能自由生成任意操作，只能从登记过的工具中选择；每个工具还应有可执行条件和可信评分。
- **对应关系：** 机器人技能库可替换成 `analyze_trial`、`compare_trials`、`optimize_parameters` 和 `check_constraints`。

### 2. Code as Policies: Language Model Programs for Embodied Control（2023）

- **做了什么：** 让 LLM 生成调用机器人感知与控制 API 的程序，并可分层生成尚未定义的辅助函数；底层 API 将生成程序约束到真实机器人能力。
- **可支持本文：** LLM 不直接处理 Speedgoat 控制量，而是通过结构化函数调用组合已有实验工具；工具接口同时提高可解释性和可复现性。
- **不能直接照搬：** 本项目不宜让 LLM 任意生成并执行代码，只允许调用白名单函数并校验参数。

### 3. Inner Monologue: Embodied Reasoning through Planning with Language Models（2023）

- **做了什么：** 把成功检测、场景信息和人工反馈写回 LLM 上下文，使 Agent 能重试、换技能、询问用户或重新规划；在仿真和真实机械臂任务中验证反馈闭环。
- **可支持本文：** 将试次质量、指标结果、安全拒绝原因和人工意见作为结构化反馈送回 Agent，使其处理“数据无效”“建议被拒绝”“目标发生变化”等情况。
- **对应关系：** 机械臂的成功检测可替换成外骨骼试次质量检查和指标改善判断。

### 4. VoxPoser: Composable 3D Value Maps for Robotic Manipulation with Language Models（2023）

- **做了什么：** LLM 将自然语言任务转成可组合的价值图和约束，传统运动规划器负责数值求解，底层控制器负责执行；论文明确指出 LLM 不适合直接输出高频控制信号。
- **可支持本文：** LLM 可以负责解释实验目标、选择指标和组织目标函数，具体参数搜索仍交给贝叶斯优化、CMA-ES 或规则工具。
- **对应关系：** “语言目标 → 目标函数配置 → 数值优化器”比“语言目标 → 力矩”更适合外骨骼。

### 5. Plug in the Safety Chip: Enforcing Constraints for LLM-driven Robot Agents（2024）

- **做了什么：** 在 LLM Agent 外增加独立约束监视器，屏蔽不安全动作，并把违反原因反馈给 LLM 重新规划；论文强调不能依靠 LLM 自身保证安全。
- **可支持本文：** `check_constraints` 必须是确定性工具。参数越界、接近力矩上限或数据质量不足时，应拒绝方案并返回明确原因。
- **对应关系：** Agent 负责提案，安全工具负责裁决，`Torque_Guard` 负责执行阶段的最终保护。

### 6. AHA: A Vision-Language-Model for Detecting and Reasoning Over Failures in Robotic Manipulation（2024）

- **做了什么：** 建立机器人操作失败数据集并训练视觉语言模型，同时判断子任务是否成功并解释失败类型，用于支持后续恢复。
- **可支持本文：** 论文可用于论证“Agent 不仅要看最终得分，还应识别失败并给出原因”。本项目不使用视觉输入，可将失败检测改为基于试次信号和确定性规则的诊断工具。
- **证据边界：** 这是机械臂视觉失败推理，不是外骨骼有效性的直接证据。

### 7. Speech-Based Human-Exoskeleton Interaction for Lower Limb Motion Planning（2023）

- **做了什么：** 将语音识别和意图识别接到有限状态机，再由 CPG 生成下肢外骨骼轨迹；有限状态机负责安全状态转换，底层位置控制器执行。论文进行了语音实验和两名健康使用者的外骨骼行走演示。
- **可支持本文：** 这是“高层自然语言/语音 → 受限意图 → 轨迹参数 → 底层控制”的直接外骨骼例子。
- **证据边界：** 它使用受限词汇和传统 NLU，不是 LLM Agent，但能证明分层接入方式在外骨骼上成立。

### 8. Learning to Assist Different Wearers in Multitasks（2024）

- **做了什么：** 在下肢外骨骼中结合 DMP、贝叶斯优化、任务转换网络、异常检测和可变阻抗控制，为不同穿戴者生成个体化轨迹；包含真实外骨骼实验。
- **可支持本文：** 直接证明 DMP、参数优化、异常评价和阻抗控制可以构成外骨骼的工具层，是与当前系统最接近的领域论文。
- **对应关系：** 可借鉴 DMP 参数搜索与安全阻抗结构，但不能直接照搬其传感器、目标函数或网络。

### 9. Human-in-the-loop Optimisation in Robot-assisted Gait Training（2025）

- **做了什么：** 使用 CMA-ES 连续优化下肢外骨骼 assist-as-needed 控制器的刚度，六名健康受试者进行了两天实验。算法得到个体化刚度，但验证阶段未观察到明确性能改善。
- **可支持本文：** 参数发生变化或优化器收敛，不等于辅助效果提升；实验必须保留基线、验证试次和失败结论。
- **对 Agent 的意义：** Agent 需要能够识别“优化没有带来实际改善”，而不是只报告成功调用了优化工具。

### 10. Comparing Optimized Exoskeleton Assistance of the Hip, Knee, and Ankle（2021）

- **做了什么：** 参数化髋、膝、踝助力曲线并进行 human-in-the-loop 优化，变量包括助力时机、幅值、膝刚度和阻尼。
- **可支持本文：** 说明时机、幅值、刚度和阻尼是可优化接口，也提示应优先选择少量参数，避免人体实验中的高维搜索。
- **证据边界：** 其主要目标是代谢成本且使用本项目没有的测量条件，因此只借鉴参数化和实验比较方法。

## 三、论文准备怎么写

### 暂定研究问题

在不改变外骨骼确定性实时控制与安全链的前提下，LLM Agent 能否通过调用受约束的实验分析与参数决策工具，根据试次反馈生成合法、可解释并可执行的下一轮实验方案？

### Introduction 主体逻辑

**第一段：外骨骼为什么需要个体化。** 不同穿戴者的步态、人与设备的匹配以及实验目标不同，外骨骼既要提供有效辅助，又要保持同步、柔顺和安全。

**第二段：已有控制基础与调参问题。** DMP 和阻抗控制提供稳定、可解释的底层控制，但 `Amplitude`、`phase_offset`、助力增益等参数仍需结合试次数据反复分析和调整。

**第三段：传统优化已经能做什么。** Human-in-the-loop、贝叶斯优化和 CMA-ES 能自动搜索外骨骼参数，但通常按照预先固定的变量、指标和流程运行；文献也表明优化收敛未必带来实际性能改善。

**第四段：LLM Agent 带来的新能力。** 通用机器人研究表明，LLM 可以从技能库中选择工具，调用确定性程序，利用执行反馈重试或重新规划，并将自然语言目标转成传统规划器可处理的任务。

**第五段：现有缺口。** 这些 Agent 方法主要用于机械臂和移动机器人，现有外骨骼研究则多采用固定语音意图或固定优化循环；LLM 如何调用外骨骼试次分析、参数优化和安全检查工具，并在不进入实时力矩环的情况下形成闭环，仍缺少具体实现和验证。

**第六段：本文工作。** 在足底压力 AO—DMP—阻抗控制系统外构建 LLM Agent，通过白名单工具读取试次反馈、生成下一轮有界参数方案，并利用离线任务和健康受试者实验评价工具调用、反馈恢复、安全性及控制效果。

### 暂定贡献

1. 提出面向膝关节外骨骼试次规划的分层 LLM Agent 架构，明确 LLM、确定性工具和实时控制器的权限边界。
2. 建立从足底压力、运动学和力矩数据到分析、比较、优化和安全检查的工具库。
3. 设计反馈闭环，使 Agent 能处理无效试次、安全拒绝、目标变化和优化无改善等情况。
4. 通过离线 Agent 任务和计划中的 8 名健康受试者实验验证可行性；不使用 EMG 或 IMU，不宣称临床疗效。

### 实验设计只保留两层

**第一层：离线 Agent 任务。** 使用历史/合成试次构造正常数据、缺失数据、异常力矩、目标变化和参数越界等场景，比较固定脚本流程、无工具 LLM 和受约束工具调用 Agent。评价任务完成率、正确工具序列、参数合法率、安全拦截率、失败恢复率和运行开销。

**第二层：健康受试者可行性实验。** 在老师确认后采用被试内比较，可考虑固定/人工参数与 Agent 辅助方案。人体指标使用现有信号可计算的跟踪误差、相位时序、力矩和安全指标；具体优化目标、条件顺序和试次数仍需结合实验负担确定。

判断 LLM 是否必要的关键是：面对目标变化、无效数据或安全拒绝时，Agent 是否比固定流程更能选择合适工具并完成任务。如果所有情况都只执行同一顺序，LLM 将缺乏必要性。

## 四、目前试验线已经完成什么

当前正式模型是 `TestStructure.slx`，实时链路为：

```text
足底压力 -> AO -> DMP -> PD/阻抗控制 -> Torque_Guard -> 力矩输出
```

当前已有第一版离线试次流程：

```text
Speedgoat File Log
-> MATLAB 归档试次
-> Python 校验数据格式
-> 计算步态与力矩指标
-> 基于固定规则提出参数调整方向
-> 生成诊断报告
```

已经完成的模块包括：

- `tools/import_slrt_filelog_trial.m`：归档 Speedgoat File Log。
- `scripts/trial_io.py`：读取并校验规范试次数据。
- `scripts/gait_analysis.py`：计算跟踪 RMSE、峰值误差、相位延迟、力矩峰值/RMS 和安全限幅比例。
- `scripts/parameter_suggestion.py`：基于阈值规则建议保持、增减或调整参数。
- `scripts/run_trial_pipeline.py`：串联分析、建议和报告。
- `scripts/test_trial_pipeline.py`：使用合成试次验证最小流程。

目前必须说明：参数建议仍是规则系统，不是贝叶斯优化；完整流程只在合成样例上验证，真实 MAT/File Log 数据仍需完成信号映射与规范化。

## 五、Agent 工具可以怎样定义

| 工具 | 输入 | 输出 | 当前状态与权限 |
| --- | --- | --- | --- |
| `import_trial` | File Log、试次元数据 | 规范试次目录 | 已有 MATLAB 原型；只归档 |
| `validate_trial` | 试次目录 | 缺失字段、质量状态 | 已有；失败则禁止后续调参 |
| `analyze_trial` | 合法试次 | 指标与事件 JSON | 已有第一版；确定性计算 |
| `compare_trials` | 多个试次 ID | 指标差异、趋势 | 待实现；不修改参数 |
| `suggest_by_rules` | 指标 JSON | 保持/增减建议 | 已有；仅离线建议 |
| `optimize_parameters` | 历史参数、指标、目标和边界 | 候选参数 | 待实现；可封装 BO/CMA-ES |
| `check_constraints` | 候选参数、质量和力矩指标 | 接受/拒绝及原因 | 待独立实现；拥有否决权 |
| `build_next_trial_plan` | 已通过检查的建议 | 结构化试次方案 | 待实现；必须人工确认 |
| `generate_report` | 指标、建议、调用记录 | 可追溯报告 | 已有第一版 |

Agent 应主要读取摘要 JSON，不直接吞入长时间原始波形；所有工具调用、输入、输出、拒绝原因和人工确认都应保存。第一版也不应自动向 Speedgoat 写参数，先以“生成下一试次方案”为执行终点。

## 六、需要老师确认的三个问题

1. 论文主问题是否确定为“LLM Agent 调用受约束的外骨骼实验工具”，而不是单独研究某一种优化算法。
2. 第一版 Agent 要解决哪些非固定场景：建议至少包含目标变化、无效试次和安全拒绝，否则难以体现 LLM 的必要性。
3. 健康受试者实验采用什么对照，以及开放哪 2～3 个参数；建议先从 `phase_offset`、`Amplitude` 和一个总体助力增益中选择。
