# 实验线 AGENTS.md

## 范围与定位

实验线负责离线试次分析、确定性工具、LLM Agent 编排、参数建议、安全验证、Speedgoat 数据接口及人体实验协议。

这是科研原型，不按 Agent 岗位面试或企业平台标准扩张。最低必要系统包括：清晰的数据/工具契约、受约束工具调用、确定性安全检查、失败处理、审计日志和人工确认。

暂不纳入：多租户权限、分布式服务、复杂长期记忆、生产级高可用、复杂 UI、LLM 直接生成安全逻辑、LLM 直接控制实时力矩、自动向 Speedgoat 下发参数。

## 模型与任务类型

- 实验问题、评价指标、系统边界、安全审查和结果解释：`gpt-5.6-sol`，`medium`。
- MATLAB/Python/Simulink 辅助代码、测试、数据转换与批处理：`gpt-5.6-luna`，`max`。

任务名使用 `<派发者>-实验-<设计|审查|代码|分析>-<目的>`。

## 系统边界

- LLM Agent 只在实时环外、按试次或窗口低频运行。
- 确定性工具完成信号检查、步态指标计算、参数边界检查和安全判定。
- Agent 可选择工具、解释结果并提出下一试次参数方案，但所有参数必须经过 schema、范围、安全规则和人工确认。
- `Torque_Guard`、`SafeTorque` 和 Saturation 是最终安全边界，不能由 LLM 绕过。
- 当前 AO 仅使用足底压力；不引入 EMG 或 IMU。

## 实验回答什么

默认 LLM Agent 是论文前提。实验重点评价：

- 工具选择与参数建议是否正确、合法；
- 异常数据、越界参数和接近安全上限时能否拒绝或恢复；
- 建议是否可解释、可复现、可追溯；
- 个体反馈或实验目标变化后能否形成合理的下一试次方案；
- 在健康受试者实验中，目标控制指标是否改善且无安全违规。

不要求额外搭建一套完整“传统系统”来证明 LLM 必要。若论文需要基线，优先复用同一套确定性工具和数据管线，只替换决策策略，避免维护两套基础设施。

## 实施与安全规则

- 工程变更在范围稳定后使用 OpenSpec，规格应包含输入输出契约、约束、日志和验收测试。
- 先做离线回放、合成异常和历史数据验证，再考虑人体试次。
- 人体实验前必须完成伦理审批/豁免、知情同意、风险处置、匿名化和数据管理要求。
- 计划招募 8 名健康受试者，在完成前不得写成既成结果。
- 原始数据不可公开上传；代码不得自动改变实时控制或硬件参数。
