## Context

仓库当前已有文献检索流程和关于 “Exoskeleton with LLM” 的路线图文档。路线图已经明确系统边界：确定性工具负责分析行走试次数据，受约束规则层负责生成低频参数建议，LLM 负责解释和报告。实时 MATLAB/Simulink + Speedgoat 控制链路仍然是执行和安全的权威链路。

目标场景是在治疗师或工程师监督下，受试者穿戴准直驱膝关节外骨骼完成直线行走任务。相关信号包括 `q_meas`、`dq_meas`、`q_ref`、`dq_ref`、`FeetLoad`、`Phi`、`Phase0Event`、`tau_e`、`SafeTorque`、患侧信息，以及当前 DMP/控制参数。

当前 Speedgoat 使用流程是：先对齐开发机 MATLAB 与 target software 版本；随后在 Simulink 中对工程模型执行 Ctrl+B 编译，生成 `.mldatx` 应用文件；再通过 SLRT Explorer 上传 `.mldatx`、运行应用，并在 SLRT Explorer 中修改运行参数。第一版数据采集设计应兼容这个人工操作流程，而不是强制改为 MATLAB 命令行自动部署。

## Goals / Non-Goals

**Goals:**

- 提供一个 Python 优先的确定性流程，把导出的试次数据转成紧凑、可追溯的指标。
- 编码保守规则，把相位、幅值、跟踪、数据质量和力矩安全指标映射到有边界的参数建议。
- 生成 LLM 可读取的 JSON 输入和人类可读的诊断报告，并能回溯到工具输出。
- 保持输出格式适合后续 Simulink 离线回放对比。

**Non-Goals:**

- 不把 LLM 放入实时力矩控制闭环。
- 不自动写入 Speedgoat 或 Simulink 运行时参数。
- 第一版不训练监督式步态状态识别模型。
- 不要求代谢仪、全身动捕或复杂 EMG 阵列等当前不稳定依赖。
- 不基于离线分析直接宣称临床疗效。

## Decisions

1. 确定性工具负责信号分析。

   流程将使用 Python 函数和脚本完成试次加载、事件检测、周期切分、参考构建、对齐和指标计算。这样可以把长时间序列处理留在 LLM 上下文之外，并保证计算过程可复现。

   备选方案是让 LLM 直接检查原始序列。该方案被排除，因为高频原始数据太大、难验证，也不适合作为控制建议依据。

2. JSON 作为工具、规则和报告之间的契约。

   工具输出将保存为结构化 JSON，例如 `trial_summary.json`、`gait_metrics.json` 和 `parameter_suggestion.json`。报告必须引用这些字段，而不是自由生成无法追溯的证据。

   备选方案是只生成 Markdown 摘要。该方案不优先采用，因为 Markdown 更难校验、比较和输入回放脚本。

3. 参数建议是离散且有边界的。

   规则层输出保持、轻微增大、轻微减小、轻微提前、轻微延后等动作。除非明确了步长和安全策略，否则不输出任意连续数值。

   备选方案是立即优化精确参数值。该方案暂缓，因为项目首先需要一个安全、可解释的基线，再考虑 Bayesian optimization 或其他搜索方法。

4. 安全和数据质量可以否决建议。

   在输出建议前必须检查 `SafeTorque`、饱和、Torque_Guard 触发、足底接触可靠性、相位可靠性和最小有效周期数。不安全或不可靠场景必须输出保守拒绝或数据质量警告。

   备选方案是始终给出最佳猜测建议。该方案被排除，因为传感器不可靠或力矩接近限幅时，参数调整很难被证明合理。

5. LLM 报告只读取压缩证据。

   LLM 读取指标、规则决策和可选短 evidence cards。默认不读取完整原始试次数组，也不得编造无证据的实验结论。

   备选方案是做开放式 RAG Agent，读取所有数据和论文。第一版不做，因为它会增加上下文负担，并削弱可审计性。

6. Speedgoat 部署和调参优先贴合现有 SLRT Explorer 流程。

   第一版不要求脚本自动构建或自动上传外骨骼工程模型。模型编译、`.mldatx` 上传、启动/停止和在线参数修改仍可由工程师在 Simulink 与 SLRT Explorer 中完成。脚本优先负责连接检查、File Log 导入、日志归档和导出分析输入。

   备选方案是用 MATLAB 脚本全自动 `slbuild`、`load`、`start` 和参数写入。该方案暂缓，因为真实外骨骼模型需要硬件连接和人工监督，自动部署/启动会增加安全风险。

## Risks / Trade-offs

- 试次导出格式不一致 -> 定义规范输入 schema，缺列时给出清晰错误。
- 足底压力或相位信号噪声较大 -> 加入可靠性标志，并允许 `Phase0Event` 与 `FeetLoad` 相互校验。
- 早期阈值可能偏主观 -> 把阈值放入配置，并在每次建议中一并记录。
- 保守建议可能显得贡献较弱 -> 将其视为安全特性，并通过专家一致性和离线回放验证。
- LLM 报告可能加入无证据解释 -> 报告只从固定 JSON 字段生成，并增加 unsupported claim 检查。
- Simulink 回放集成可能慢于 Python 工具实现 -> 第一阶段通过文件接口解耦，把回放作为后续验证步骤。
- 自动部署外骨骼模型存在安全风险 -> 外骨骼工程模型继续通过 SLRT Explorer 人工上传、运行和调参，脚本只做只读诊断和日志处理。

## Migration Plan

1. 添加 OpenSpec specs 和 tasks，定义第一版实现边界。
2. 实现可从项目根目录运行的 Python 脚本，并把输出写入 `analysis_outputs/`。
3. 按现有流程在 SLRT Explorer 中上传和运行 `.mldatx`，并启用 File Log 记录关键试次信号。
4. 将目标机 File Log 导入 MATLAB/SDI，并导出为规范 CSV 或 MAT。
5. 用导出的试次数据运行 Python 分析流程。
6. 对照 JSON 输出审查报告，并调整阈值。
7. 文件契约稳定后，再加入 Simulink 离线回放对比。

第一阶段的回滚很简单：删除生成的分析输出即可，不修改运行时控制器文件。
