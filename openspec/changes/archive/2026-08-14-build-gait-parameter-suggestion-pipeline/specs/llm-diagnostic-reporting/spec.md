## ADDED Requirements

### Requirement: 仅使用结构化输入
报告层 SHALL 消费结构化指标和建议文件，而不是原始高频试次数组。

#### Scenario: 报告输入可用
- **WHEN** 试次指标和参数建议以 JSON 文件形式存在
- **THEN** 报告层使用这些文件作为诊断报告的证据来源

#### Scenario: 直接提供原始数据
- **WHEN** 调用方尝试在没有结构化指标的情况下，直接用原始长序列数据生成报告
- **THEN** 报告层拒绝，并提示调用方先运行确定性分析

### Requirement: 报告绑定证据
报告层 SHALL 生成可追溯到指标字段和规则输出的解释。

#### Scenario: 有证据支撑的结论
- **WHEN** 报告陈述相位、幅值、跟踪、力矩或可靠性结论
- **THEN** 报告引用对应的指标字段或规则理由

#### Scenario: 证据缺失
- **WHEN** 某项结论缺少证据
- **THEN** 报告将该结论标记为不可用，而不是推断生成

### Requirement: 控制边界约束
报告层 SHALL NOT 声称能够直接控制、更新或覆盖外骨骼控制器。

#### Scenario: 报告包含参数建议
- **WHEN** 报告列出建议的参数调整
- **THEN** 报告说明该调整需要人工确认后，才能进入 Simulink 或 Speedgoat 更新流程

#### Scenario: 不安全的直接控制请求
- **WHEN** 调用方要求报告层输出电机力矩、绕过 Torque_Guard 或直接写入实时参数
- **THEN** 报告层拒绝，并记录该请求超出系统边界

### Requirement: 报告产物生成
报告层 SHALL 为每个已分析试次写出人类可读的报告产物。

#### Scenario: 报告生成成功
- **WHEN** 提供有效的指标 JSON 和建议 JSON
- **THEN** 系统写出 Markdown 报告，包含试次身份、数据质量、关键指标、建议摘要、安全检查和人工确认状态

#### Scenario: 报告发现无证据结论
- **WHEN** 报告校验步骤发现无法追溯到输入字段或规则的结论
- **THEN** 系统将报告标记为无效，直到这些结论被移除或补充证据
